DSA Mini-Project Architecture

1. Priority Min-Heap Allocation

The system stores vacant bays inside a binary Min-Heap. The heap invariant guarantees the bay with minimal distance $d$ to the gate is positioned at root $i = 0$. extractMin() executes in O(log N), sifting down in logarithmic time.

2. Starvation Prevention (Aging in Max-Heap)

When all matching slots are occupied, incoming vehicles enter a Max-Heap Waiting Queue. To prevent regular cars from starving due to VIP arrivals, an aging algorithm adds $+10$ points for every minute waited.

3. Automated Reallocation Trigger

When a bay is released, the system calculates parking fee, updates the database, and immediately dequeues the top waiting vehicle from the Max-Heap, auto-allocating the bay without human intervention!

Project Synopsis & Lab Viva Reference

Smart Parking Search & Allocation System

Course: Data Structures and Algorithms (Mini Project) • Semester V

1. Problem Definition

Traditional parking lots suffer from inefficient manual or linear searches, resulting in $O(N)$ allocation latency, vehicle queuing, and congestion. The objective of this project is to model parking spaces as a dynamic ordered priority data structure, reducing search and allocation complexity to $O(\log N)$ using Min-Heaps and Binary Search.

2. Key Technical Objectives

  • Maintain available bays in strictly sorted order by proximity distance $d$.
  • Provide instant $O(\log N)$ lookup using Binary Search for bay IDs or distance ranges.
  • Implement Min-Heap allocation where the root holds the closest vacant space.
  • Prevent starvation in waiting vehicles queue via an Aging Algorithm.

4. Essential Viva Voce Questions & Answers

Q1: Why use a Min-Heap instead of a Sorted Array for slot allocation?

Answer: In a sorted array, peeking the closest bay is $O(1)$, but removing it requires shifting all $N-1$ elements, taking $O(N)$ time. When a car departs and the bay is released, re-inserting it into a sorted array also takes $O(N)$ due to element shifts. In contrast, a Min-Heap achieves $O(\log N)$ for both extraction and insertion. For $N = 10,000$ bays, $\log_2(10000) \approx 14$ operations versus up to 10,000 shifts in an array.

Q2: How does the system prevent vehicle starvation in the waiting queue?

Answer: If higher-priority vehicles (e.g. VIP or emergency vehicles) arrive continuously, standard vehicles could wait indefinitely (starvation). We implement an Aging Algorithm: $$\text{Priority Score} = \text{Base Priority} + (\text{Minutes Waited} \times 10)$$ Over time, a regular vehicle's score naturally exceeds newly arriving VIP vehicles, guaranteeing eventual service without deadlock.

Q3: How is Binary Search applied to slot maintenance?

Answer: Vacant slots are kept sorted by distance or bay ID. Binary search maintains three pointers: low, mid = low + (high - low) / 2, and high. At each iteration, comparing the middle element with the target eliminates half of the remaining search space, guaranteeing lookup in $\le \lceil \log_2 N \rceil$ steps. It also computes the insertion point when new bays are commissioned.
